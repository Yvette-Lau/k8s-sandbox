# Complete Lab Guide: Monitoring Pod Traffic with tcpdump in Kubernetes

This guide will walk you through the process of creating a pod, identifying the correct network interfaces, and capturing traffic going in and out of the pod using tcpdump.

## Prerequisites

- Access to a Kubernetes cluster (EKS in this example)
- kubectl installed and configured
- SSH access to the worker nodes (or ability to run privileged containers)
- tcpdump installed on the nodes

## Step 1: Create a Test Pod

Let's create a simple pod that generates some network traffic:

```bash
# Create a namespace for our test
kubectl create namespace traffic-test

# Create a test pod
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: traffic-generator
  namespace: traffic-test
  labels:
    app: traffic-generator
spec:
  containers:
  - name: traffic-generator
    image: nicolaka/netshoot
    command: ["sleep", "3600"]
EOF

# Create a service to send traffic to
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: nginx-server
  namespace: traffic-test
  labels:
    app: nginx
spec:
  containers:
  - name: nginx
    image: nginx
---
apiVersion: v1
kind: Service
metadata:
  name: nginx-service
  namespace: traffic-test
spec:
  selector:
    app: nginx
  ports:
  - port: 80
    targetPort: 80
EOF
```

## Step 2: Wait for Pods to be Ready

```bash
kubectl wait --for=condition=Ready pod/traffic-generator -n traffic-test
kubectl wait --for=condition=Ready pod/nginx-server -n traffic-test
```

## Step 3: Identify the Node Hosting Your Pod

```bash
# Get the node where the traffic-generator pod is running
NODE=$(kubectl get pod traffic-generator -n traffic-test -o jsonpath='{.spec.nodeName}')
POD_IP=$(kubectl get pod traffic-generator -n traffic-test -o jsonpath='{.status.podIP}')

echo "Pod is running on node: $NODE with IP: $POD_IP"
```

## Step 4: SSH into the Node

```bash
# For AWS EKS, you might use SSM
aws ssm start-session --target i-xxxxxxxxxxxx  # Replace with your node's instance ID

# Or traditional SSH
ssh ec2-user@$NODE_IP  # Replace with appropriate username and IP
```

## Step 5: Identify the Network Interface for the Pod

Once logged into the node:

```bash
# View routing table to find the interface associated with the pod IP
sudo ip route show | grep $POD_IP

# Example output:
# 192.168.35.77 dev enif0f164e3088 scope link
```

The output shows the virtual ethernet interface that connects to your pod. Note the interface name (e.g., `enif0f164e3088`).

## Step 6: Capture Traffic with tcpdump

Now you can use tcpdump to monitor traffic on this interface:

```bash
# Basic capture
sudo tcpdump -i enif0f164e3088

# More detailed capture with packet contents
sudo tcpdump -i enif0f164e3088 -n -vv

# Capture specific traffic (e.g., HTTP)
sudo tcpdump -i enif0f164e3088 -n 'tcp port 80'

# Save capture to a file
sudo tcpdump -i enif0f164e3088 -w pod_traffic.pcap
```

## Step 7: Generate Test Traffic from the Pod

In a separate terminal:

```bash
# Execute commands in the pod to generate traffic
kubectl exec -it traffic-generator -n traffic-test -- curl nginx-service.traffic-test.svc.cluster.local

# Or ping external sites
kubectl exec -it traffic-generator -n traffic-test -- ping -c 5 google.com
```

## Step 8: Analyze the Captured Traffic

Back in your tcpdump terminal, you should see the traffic generated by your commands. Press Ctrl+C to stop capturing.

If you saved the capture to a file, you can analyze it in more detail:

```bash
# On the node
sudo tcpdump -r pod_traffic.pcap -n

# Or transfer the file to your local machine for analysis with Wireshark
```

## Alternative: Using a Privileged Container for Capture

If you don't have direct SSH access to nodes, you can deploy a privileged container:

```bash
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: network-debugger
  namespace: traffic-test
spec:
  hostNetwork: true
  containers:
  - name: debugger
    image: nicolaka/netshoot
    command: ["sleep", "3600"]
    securityContext:
      privileged: true
EOF
```

Then:

```bash
kubectl exec -it network-debugger -n traffic-test -- bash
# Now you can run the same ip route and tcpdump commands from inside this pod
```

## Understanding Network Interfaces

In Kubernetes with AWS VPC CNI:

1. `eth0` - The main network interface of the node
2. `enif0f164e3088` (or similar name) - The virtual ethernet interface that connects to your pod
3. Inside the pod, there's an `eth0` interface that is paired with the host-side interface

The traffic you see on the host-side interface (`enif0f164e3088`) is exactly what goes in and out of the pod.

## Clean Up

```bash
kubectl delete namespace traffic-test
```

This lab guide demonstrates how to monitor the network traffic for a specific pod by identifying and capturing packets on the correct network interface on the host node.
